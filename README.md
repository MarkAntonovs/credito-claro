# Credito Claro

I want to redesign an existing Colombian financial comparison website:

https://creditocolombia.co/

IMPORTANT:

This is currently a DESIGN / PRODUCT EXPLORATION stage.

Do NOT try to migrate the existing website.

Do NOT reproduce its current visual design.

Do NOT build dozens of pages.

Do NOT assume that the current lender data or financial claims are accurate.

For now, I want you to plan a completely redesigned HOMEPAGE and a reusable visual system for the future website.

PROJECT

Brand: ColombiaCredito.co

ColombiaCredito.co is an independent informational and affiliate comparison website for users in Colombia who want to understand and compare credit options.

It is NOT:

- a bank

- a lender

- a financial institution

- a loan approval service

It does not issue or approve loans.

Some outbound links may be affiliate links and the website may receive compensation when users follow them or obtain a product.

The product must clearly distinguish:

1. direct credit providers

2. brokers / comparison / intermediary services

The website operates in a financial/YMYL category, so transparency and trust are extremely important.

PRIMARY GOALS

The homepage should:

1. Immediately explain what ColombiaCredito.co does.

2. Help a Colombian user start comparing credit options.

3. Look trustworthy enough for a financial decision.

4. Direct users toward the main credit categories.

5. Preview real comparison functionality.

6. Explain why users can trust the information.

7. Make affiliate/commercial relationships transparent.

8. Lead users naturally toward commercial provider pages without feeling aggressive.

9. Work extremely well on mobile.

10. Establish a reusable design system for all future pages.

DESIGN DIRECTION

Create a modern Colombian financial comparison product.

Desired feeling:

- trustworthy

- calm

- modern

- independent

- useful

- transparent

- locally relevant to Colombia

- premium enough to feel credible

- simple enough for non-financial users

It should feel closer to a serious modern comparison/fintech product than an affiliate blog.

DO NOT make it look like:

- a payday-loan spam website

- a casino

- a crypto landing page

- a fake bank

- a generic SaaS template

- a government website

- an aggressive lead-generation funnel

Avoid:

- huge gradients

- excessive glassmorphism

- neon colors

- excessive rounded cards everywhere

- fake testimonials

- fake star ratings

- fake trust badges

- stock photos of people holding cash

- countdown timers

- "APPROVED!"

- "100% approval"

- "money in 5 minutes"

- misleading urgency

- decorative elements that make financial information harder to read

VISUAL IDENTITY

Do not copy Hoy.credit.

ColombiaCredito.co should have its own recognizable visual identity.

Explore a sophisticated palette based around:

- warm off-white / very light neutral backgrounds

- deep navy, ink, or charcoal for primary text

- one restrained Colombian-inspired accent

A Colombian reference can be subtle.

Do NOT simply make the website yellow + blue + red like the Colombian flag.

Typography should feel editorial and financial rather than startup-gimmicky.

Use strong typography hierarchy.

Headings can have some character, but body text and financial data must be extremely readable.

Use generous spacing.

Cards should be structured and information-dense without feeling crowded.

The design should communicate:

"we help you understand the market"

rather than:

"we desperately want you to click APPLY".

HOMEPAGE STRUCTURE

Design the homepage around approximately this information architecture.

1. HEADER

Brand/logo:

ColombiaCredito.co

Navigation should be simple.

Possible navigation:

Comparar

Tipos de crédito

Guías

Cómo comparamos

Nosotros

There should be a clear but non-aggressive CTA such as:

"Comparar opciones"

Mobile navigation must be considered from the beginning.

2. HERO

Primary direction:

"Compara opciones de crédito en Colombia"

Supporting copy should explain that users can compare providers, requirements, amounts and relevant conditions before deciding.

Include one clear primary CTA:

"Comparar opciones"

Potential secondary action:

"Cómo funciona"

VERY IMPORTANT:

Near the hero or immediately below it, clearly communicate:

"ColombiaCredito.co no es una entidad financiera y no otorga créditos."

This should be visible but not designed as a scary legal warning.

Do not claim:

- guaranteed approval

- best rates

- lowest rates

- instant funding

unless those claims could actually be proven.

3. TRUST / TRANSPARENCY STRIP

Create a compact section communicating ideas such as:

Información verificada

Fuentes identificadas

Publicidad claramente indicada

Do not use fake certifications.

This section should visually establish trust early.

4. CREDIT CATEGORY NAVIGATION

Section idea:

"Encuentra información según tu situación"

Main categories:

Créditos online

Pensionados

Reportados / historial crediticio

Independientes

These should be visually distinctive but should NOT look like four generic feature cards from a SaaS template.

Each should briefly explain the user's situation.

5. COMPARISON PREVIEW

This is one of the most important components.

Create a reusable ProviderCard component.

For design purposes use clearly marked SAMPLE / PLACEHOLDER DATA rather than inventing real financial conditions.

The component must support:

Provider logo

Provider name

Provider type badge

Example types:

"Proveedor directo"

"Servicio de comparación"

Product type

Amount range

Term or eligibility information

Important requirements

Cost/rate information

Last verification date

Primary commercial CTA

Secondary "Ver detalles" action

Example structure:

Lineru

Proveedor directo

Cupo de crédito rotativo

Monto:

[verified value]

Requisitos:

[verified values]

Tasas y costos:

[verified information or "No disponible"]

Información verificada:

[date]

[Ver detalles]

[Ir al proveedor]

For an intermediary such as a comparison service, the visual treatment should make it impossible to mistake it for the lender.

For example:

CREZU

Servicio de comparación

"No otorga el crédito directamente."

The component must gracefully support unknown data:

"No disponible"

Do not design the component around every field always existing.

Affiliate CTA hierarchy should be strong enough for conversion but not manipulative.

6. AFFILIATE DISCLOSURE

Near the comparison product, create a concise disclosure component.

Example concept:

"Algunos enlaces son de afiliados. Podemos recibir una comisión si solicitas un producto a través de ellos. Esto no aumenta el costo para ti."

Include a contextual link to:

"Cómo funciona nuestra metodología"

The disclosure should be visible and understandable, not hidden in tiny gray text.

7. HOW COMPARISON WORKS

A compact section explaining something like:

1. Revisamos información de proveedores.

2. Organizamos las opciones para facilitar la comparación.

3. Tú revisas las condiciones finales directamente con el proveedor.

Do not imply that ColombiaCredito approves applications.

8. DECISION / EDUCATIONAL SECTION

Create a useful section:

"Qué revisar antes de solicitar un crédito"

Possible concepts:

Tasa y costo total

Plazo

Cuota

Requisitos

Consecuencias de mora

This should establish expertise without turning the homepage into a huge article.

9. RESPONSIBLE BORROWING

A restrained informational section explaining that borrowing has costs and users should evaluate their ability to repay.

Do not make it preachy.

10. GUIDES

Create an editorial-content preview for important guides such as:

Tasas de interés

Tasa de usura

Historial crediticio

Cómo identificar estafas

Derechos del consumidor financiero

This area should look editorial rather than like another set of commercial cards.

11. METHODOLOGY / EDITORIAL TRUST

Create a visually strong section explaining:

- how information is checked

- that financial information can change

- that final conditions must be confirmed with the provider

- that commercial relationships are disclosed

- that compensation does not turn ColombiaCredito.co into a lender

Link toward:

Metodología

Política editorial

Divulgación de afiliados

12. FOOTER

The footer architecture should anticipate:

Comparar

Tipos de crédito

Guías

Sobre nosotros

Metodología

Política editorial

Divulgación de afiliados

Privacidad

Términos

Contacto

Include a concise disclaimer that ColombiaCredito.co is not a lender.

Future pages will include:

commercial comparison pages

credit-category landing pages

provider profiles

financial guides

trust/editorial pages

legal pages

Therefore design the system so those future page types feel like one coherent product.

MOBILE

Mobile is extremely important.

Do not simply shrink desktop.

Provider cards must remain easy to scan.

Important financial information and CTA should remain visible without overwhelming the user.

Navigation should be simple.

Avoid giant hero sections that consume the entire first screen on mobile.

SEO / ACCESSIBILITY CONSTRAINTS

The eventual implementation must support:

semantic HTML

one logical H1

SSR

crawlable text

breadcrumbs

accessible contrast

keyboard navigation

descriptive links

visible focus states

fast loading

minimal layout shift

responsive images

Do not make important text part of images.

Do not depend on JavaScript animation to reveal indexable content.

Animation should be subtle and optional.

IMPORTANT CONTENT RULE

Do not invent:

interest rates

loan amounts

approval times

regulatory status

licence claims

provider rankings

customer ratings

number of customers

approval percentages

Use obvious placeholder values where financial/provider data is necessary to demonstrate the UI.

Unknown information must be supportable as:

"No disponible"

DELIVERABLE FOR THIS STAGE

First propose a concise design/product plan covering:

1. visual direction

2. color philosophy

3. typography direction

4. homepage hierarchy

5. comparison-card approach

6. trust/transparency treatment

7. mobile approach

8. reusable component system

Then implement ONLY the homepage/design system needed to demonstrate this direction.

Do not generate the full production website yet.

The objective is to create a polished visual prototype that we can review before deciding on the final technical implementation and migration.
